## Context

“帮帮帮”互助小程序面向社区老年群体和年轻志愿者，需要兼顾**极致适老化的交互体验**（大字号、高对比度、大热区、语音输入指引）以及**互助闭环的高可玩性**（抢单接单、即时沟通、动态广场、金币积分兑换）。
用户明确要求：**UI 必须严格 100% 还原 `/docs/ui/` 原型稿**（包括页面布局、主题色彩蓝/黄/白、卡片圆角投影、双端标签与图标元素）。为了保证在无独立后端服务环境下即可直接在微信开发者工具或真机中体验全部业务流程，系统架构采用 Uni-app (Vue 3 + TS) + Pinia 状态层 + Storage 本地持久化驱动。

## Goals / Non-Goals

**Goals:**
- **严格还原原型稿 UI**：基于 `/docs/ui/` 包含的全部页面（首页、订单页、下单页、接单页、消息列表、通讯录、聊天室、广场、兑换商城、购物车、物流追踪、个人资料、实名认证、字体大小调节等）进行像素级布局与样式对齐。
- **端到端交互闭环**：实现老人端一键/分类求助下单 ➔ 志愿者接单 ➔ 建立私信沟通 ➔ 订单完成 ➔ 发放金币 ➔ 商城兑换物资 ➔ 运单物流追踪全流程。
- **全局适老字体缩放**：实现与原型稿滑块一致的字号级别切换（小、标准、大），所有页面根据缩放比动态调整文字大小与点击区域。
- **本地 Mock 与持久化**：统一 Service 接口层，封装 Pinia Store 与 `uni.setStorageSync`，离线状态下刷新数据不丢失，并可平滑切换后续真实接口。

**Non-Goals:**
- **初期接入真实第三方支付与运单网关**：金币兑换与下单金额初期走虚拟金币核算，物流轨迹采用真实节点的仿真流转，不接入真实外部中通物流 API。
- **复杂后端微服务部署**：第一阶段聚焦于小程序前端工程、交互体验与 Mock 业务闭环，不涉及云服务器后端微服务部署。

## Decisions

### 1. 采用 Uni-app (Vue 3 + TypeScript + Vite + Pinia)
- **选择理由**：Vue 3 组合式 API (Composition API) 适合抽离通用逻辑（如字号缩放 hook、语音录入 mock、消息轮询/模拟响应）；TypeScript 提供严格的类型定义（Order, User, Message, Mall 等实体）；Pinia 能够清晰组织各个功能模块的响应式状态。
- **替代方案对比**：微信原生框架代码分散且缺少统一的现代工程化包管理；Taro 偏向 React，而在中文及适老项目中 Uni-app 的微信兼容性与文档生态更优。

### 2. 严格对齐 `/docs/ui/` 原型稿视觉规范
- **主色调**：科技与温和兼具的活力蓝 `#1B65F0`（主按钮、顶部标题、激活态），辅助提示橙黄 `#FFA940` / `#FA8C16`（私信入口、兑换高亮），背景灰 `#F6F7FB`，文字深度灰 `#1F2329`，辅助浅灰 `#8F959E`。
- **适老设计**：大圆角（`24rpx` ~ `32rpx`）、大边距、大卡片阴影、表单输入框高度不低于 `96rpx`，底部操作按钮高度不低于 `100rpx`。
- **全局字体缩放体系**：
  采用 CSS 变量 `--font-scale` 驱动根节点，基准字号为 `32rpx`，在用户拖动调节滑块时，通过 Pinia `SettingStore` 将 `scale` 设为 `[0.85, 1.0, 1.15, 1.3]`，使得全局尺寸成比例无损缩放。

### 3. 数据层架构：Service 抽象 + Pinia + Storage 持久化
- **架构流向**：`Vue 视图组件` ➔ `Pinia Store Action` ➔ `Service API (Mock 实现)` ➔ `本地 Storage`。
- **内置初始种子数据 (Seed Data)**：小程序启动时，若本地 Storage 为空，自动注入预设的老人账号、志愿者账号、示例订单（医院陪诊、帮抢鸡蛋）、示例动态与商城物品（鸡蛋/盒 1000金币、纸巾/盒 500金币等），让用户一打开即有逼真的全量内容。

### 4. 即时私信与通讯录联动机制
- **通讯录**：维护静态好友列表，自动按中文姓名首字母排序归入 A-Z 字母索引栏，支持点击首字母快速锚点定位。
- **私信**：每个互助订单在接单成功后自动生成一条 `relatedOrderId` 绑定的会话，点击可直接展开订单摘要并收发文字、模拟图片、语音条等。

## Risks / Trade-offs

- **[风险] 微信小程序原生 TabBar 字号与图标无法随全局 CSS 变量缩放**
  - **缓解方案**：采用微信小程序自定义 TabBar 组件 (`custom-tab-bar`)，使 5 个底栏图标与文字尺寸完全纳入全局响应式字号系统控制。
- **[风险] 适老超大字体可能在窄屏机型上产生文字溢出折行**
  - **缓解方案**：卡片布局采用 Flex 自适应排版配合 `min-height`，关键金额与状态标签限制最小伸缩比例，避免文字重叠。
- **[风险] 语音录音与即时通话在不同机型的权限限制**
  - **缓解方案**：底部语音条支持微信原生录音 API (`uni.getRecorderManager`)；如果未授权或在开发者工具环境，自动降级为“模拟长按语音条并自动填充预设需求文字”，保障无障碍演示。
